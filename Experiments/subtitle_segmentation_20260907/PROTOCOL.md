# Text-only subtitle segmentation experiment

Date: 2026-09-07. App and worker commits, source hashes, dataset hash and local toolchain are in `manifest.json`.

## Scope and contract

Input is ordered `segments[]` with IDs, original text and speaker. Each of the 65 samples contains two relatively long segments from one speaker. `join_policy=exact_concatenation` makes their seam unambiguous. Alternate seams land near the middle of a phrase or at an annotated reference boundary. An ASR segment seam is not a compulsory cue boundary. Different speakers and explicit editing barriers would be hard boundaries in a product implementation; this dataset does not test them.

Output is an ordered list of subtitle cues. It must reproduce the original input except for whitespace exposed at cue boundaries. Existing internal whitespace, punctuation, accents, repetitions and apparent ASR mistakes must remain unchanged. No translation, correction, word alignment, start/end times, reading-speed or audio evaluation is performed. Experimental source offsets are Unicode code-point offsets; the corpus is NFC and does not contain multi-scalar grapheme clusters. A Swift integration must choose and test its index representation explicitly.

## Data

20 English, 20 Simplified Chinese, and 5 each Japanese, German, French, Spanish, Brazilian Portuguese. Each contains 136–506 characters depending on script. Topics cover movement instruction, editing, numbers, names, negation, dialogue, lists, code switching, self-correction, compound words, abbreviations, punctuation, and identifiers. Several non-English samples parallel English topics, intentionally controlling content; they are not 65 statistically independent real recordings. `zh-Hans-01` adapts the user-supplied screenshot wording and adds a synthetic continuation. References and protected phrases are assistant-authored diagnostics, not certified native-speaker gold labels. Protected phrases are partial: a zero count does not prove all linguistic boundaries are natural.

13 development and 52 evaluation IDs were assigned before model calls. No reference boundary, protected-span annotation or split label is included in model prompts or rule inputs. The hybrid reward sweep was added after observing the first Gemini outputs, so this is an exploratory study; the evaluation split must not be represented as a pristine external holdout. The second-model run reuses the frozen prompts, algorithm and reward values.

## Factors

- Default budgets: zh/ja minimum 8, target 14, maximum 18; other languages 24/42/56. Minimum is advisory for improved conditions. These are app settings, not universal subtitle standards.
- Wider ceiling: zh/ja 24, other languages 72; minimum and target stay fixed. This isolates the effect of relaxing the maximum.
- R0: actual Swift `SubtitleReadabilityPolicy`, original tokenizer and display join helpers, extracted unchanged at runtime and compiled using `swiftc -O`. This is the text fallback seam, not an emulation of the timed pipeline.
- R1: Apple NLTokenizer candidates for zh/ja, whitespace-word boundaries elsewhere; punctuation/particle/function-word penalties plus dynamic programming over legal lengths. It always slices the original string. No reference lexicon is consulted. Candidate punctuation rules intentionally remain frozen after first execution; French closing guillemets and mixed-script decimals expose limitations.
- R1-isolated: same algorithm, independently segment the two halves, then concatenate cues. This is the batching ablation.
- L0: exact current Mac app segmentation system/user prompts generated by Swift.
- LW: exact worker `_build_split_only_prompts` function, extracted through Python AST; matched app budgets. Correction, timing, context summaries and worker retries are excluded. The existing output requests an extra batch summary.
- L1: explicit phrase/lexical/negation/number/name protection, original `segments[]`, plain JSON text lines. The frozen prompt is in `run.py` and each raw receipt.
- L2: same semantic instructions but select monotonic end IDs over precomputed lexical atoms; reconstruct exclusively from original text. No reference offsets are provided.
- H2: use valid L2 boundaries as weighted DP preferences, with final source slicing and maximum-length enforcement; reward 2.5.
- H1: exact-match validate L1 text, convert valid text lines to source boundaries, then apply the same DP. Invalid proposals are discarded and explicitly recorded as fallback. Reward sweep 0.5, 1.0, 1.5, 2.5 (named `H1_text_dp`). This is local postprocessing of recorded model outputs, not new model inference.
- L0-length-repair: apply actual Swift length repair if an exact-text L0 cue is overlong. This does not simulate full pipeline retries or word-count guards. Gemini did not trigger repair in its first runs.

DP cost per cue: normalized squared target deviation + 0.65 cue cost + normalized shortfall below advisory minimum; add 0.7 for a nonpunctuated internal boundary, subtract 0.8 for strong punctuation or 0.25 for weak punctuation; add language-specific function-word/particle costs and 0.8 per internal strong mark, except numeric decimal points. Subtract the specified proposal reward at proposed boundaries. Over-budget edges are excluded unless a single atomic unit is indivisible, in which case an explicit overlong cue is kept and measured. Candidate sets and prefix text are bounded by these short experimental inputs; this Python prototype is not a production performance implementation.

## Model controls and execution

Per model: 65 × 4 default prompt conditions + 65 wider-ceiling L2 runs + 14 sentinel samples × 2 repeated conditions = 353 requests. Sentinel samples are IDs 01 and 05 in each language, for L1 and L2. Three concurrent HTTP requests maximum. One transport retry for selected transient errors; no automatic semantic retry. All raw responses, prompts, actual model versions, timestamps, finish reasons, usage and elapsed times are retained. Main tables exclude sentinel repeats.

After observing the nano minimal run, a separate low-reasoning ablation was added: L1 only, 65 first runs plus the same 14 sentinel repeats, 79 requests. All prompts and local algorithm weights remain frozen. The complete study therefore has 785 matrix requests plus two connectivity/model-resolution probes. Low output completion-token limits remain 4096 including reasoning tokens.

Gemini: fixed `gemini-3.5-flash-lite`, temperature 0, JSON MIME type, 4096 output-token cap. This version was obtained by probing the worker's configured `gemini-flash-lite-latest` alias. GPT: user-requested GPT-5 nano, fixed snapshot `gpt-5-nano-2025-08-07`, minimal reasoning, JSON object format, 4096 completion-token cap, temperature omitted because this model does not accept it. GPT completion tokens may include reasoning; provider tokenizers differ. Comparisons characterize these configurations, not equal inference compute. Probe requests are separate from the 353-run matrix.

Credentials are read in memory from the already configured worker provider settings. They are not copied into artifacts. The online matrices contain only the authored benchmark text, including the screenshot-inspired sample; local saved-project evidence is inspected separately and never submitted to model APIs.

## Metrics and interpretation

1. Exact reconstruction / valid sample: every cue can be consumed as a contiguous, ordered span of source text, skipping only boundary whitespace. Malformed, missing, changed and duplicated text fails.
2. Overlong cues and feasible samples: based on the relevant ceiling; invalid samples are never successes.
3. Protected-phrase breaks: number of cut positions strictly inside annotated phrase occurrences. Denominator is phrase occurrences in valid samples. Overlapping annotations can count independently.
4. Punctuation starts: cue begins with a covered closing/sentence mark; quote handling is a heuristic, not a full Unicode typography engine.
5. Short cues: below the advisory minimum; not intrinsically wrong, but an over-fragmentation indicator.
6. Boundary F1: exact source-position agreement with one authored reference. Report micro, valid-sample macro and all-sample macro (invalid samples score zero). It is not a percent naturalness score or a human quality rating. Wider ceilings can legitimately reduce agreement with the same reference.
7. `safe_samples`: exact text, no overlong cue, no annotated phrase break, no covered punctuation start. This combines only the measured constraints, not all linguistic quality.
8. Observed request median latency and provider token usage. Local R1 excludes NLTokenizer work, while R0 includes its own tokenizer/join work; do not claim a production speedup from this asymmetric measurement.
9. Repeat stability: byte-identical line arrays across two calls on 14 sentinel samples. No significance claim from two runs.

## Reproduction

Run from repository root:

```bash
python3 experiments/subtitle_segmentation_20260907/prepare.py
python3 -m unittest discover -s experiments/subtitle_segmentation_20260907 -p 'test_*.py' -v
python3 experiments/subtitle_segmentation_20260907/run.py
python3 experiments/subtitle_segmentation_20260907/run.py --provider openai
python3 experiments/subtitle_segmentation_20260907/run.py --provider openai --reasoning low
python3 experiments/subtitle_segmentation_20260907/analyze.py
python3 experiments/subtitle_segmentation_20260907/analyze.py --provider openai
python3 experiments/subtitle_segmentation_20260907/analyze.py --provider openai --reasoning low
python3 experiments/subtitle_segmentation_20260907/deliver.py
python3 experiments/subtitle_segmentation_20260907/verify.py
```

Existing matching raw-request fingerprints are reused. To measure a fresh run, preserve the old `raw` directory separately before execution. Do not compare a partially completed directory with a full one. `prepare.py` reads the current source; inspect manifest hashes when reproducing against later commits. No app production source or user project is mutated by these scripts.

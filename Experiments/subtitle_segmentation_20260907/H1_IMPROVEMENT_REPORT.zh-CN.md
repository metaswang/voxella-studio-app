# GPT-5 nano：H1 前置步骤改进实验

## 结论

推荐 `gpt-5-nano-2025-08-07 + minimal + guarded lossless projection + local DP`。

它保留旧 H1 对完全正确输出的处理，只在全文校验失败时，从模型输出中局部恢复能在原文中精确定位的边界。`changed_text` 仍可能发生在模型原始回复里，但不再等价于“整份建议作废”。

在 52 条未参与调参的 evaluation 样本上：

- 旧 `H1_text_minimal`：模型建议全文有效 38/52，14 条全量降级；其中 13 条是 `changed_text`。
- 推荐组：51/52 至少恢复一个可用边界，仅 1 条全量降级。
- 最终宏平均 F1 与旧 H1 完全相同，均为 0.8607；保护短语断裂同为 3，短 cue 同为 3。
- 使用相同的一次模型调用，API token、成本和延迟没有增加。
- 在有两次重复结果的 14 条样本上，最终切法完全一致从 11/14 提升到 12/14。若对所有结果统一采用较弱投影奖励，一致率为 13/14，但 evaluation F1 轻微下降 0.0011。

## 为什么 guarded projection 有效

旧校验是 all-or-nothing。模型输出 12 条 cue，只要其中一条漏掉一个词，`locate()` 就停止，前面已经正确的 5 个边界和后面仍能精确定位的边界全部丢失。

新流程把两个问题分开：

1. 文本可信度：最终字幕永远由 source 切片，模型字符永不进入结果。
2. 边界可信度：一条模型行只有在 source 的当前游标处匹配，或能在后续唯一重同步时，才贡献其行末边界。

因此错误的局部影响被限制在该行附近。DP 继续负责硬长度、完整覆盖、标点与本地语法惩罚。

## 截图样本 `zh-Hans-01`

低推理档原回复删除了 `这个` 和 `调整，所以这个动作是很重要的。`，旧 H1 判为 `changed_text` 并完全回退 R1。

投影器仍从 12 条输出行中恢复了 12 个原样匹配行末，并发生 2 次安全重同步。纯投影组把该样本从 10 条 R1 cue 改为 11 条，F1 从 0.696 提到 0.750，且保护短语断裂为 0。关键差异是恢复了：

```text
先做一个起头的动作，
整个把这个髂骨跟肩椎的这个卡住
这个关节面先把它打开。
```

被模型删除的字符没有进入最终结果；DP 从完整 source 恢复了它们。

## 未采用的方案

`H1_boundary_ratings` 从协议安全性看是成功的：65/65 首次调用都可解析，且 evaluation 稍高于纯 R1（0.8492 对 0.8432）。但 nano 的逐边界标签仍不稳定，三次重复后单次最终切法只有 5/13 完全一致。它适合作为后续研究方向，暂时不优于 guarded projection。

`H1_nbest_choice` 的输出最短、最快、零降级，但模型没能可靠选出最好候选。evaluation F1 只有 0.8166；同一候选集的 oracle 上限为 0.9058，说明问题出在 nano 的全局选择能力，不是候选集覆盖不足。

`H1_sparse_ids` 对小模型过于开放。典型回复会把几乎所有 ID 同时列进 `prefer` 和 `avoid`，局部冲突过滤后没有信息，且总体 F1 明显下降。

三次 boundary rating 多数投票增加约三倍 token，质量反而回落到 0.8426；不值得投入生产。

低推理档的无损投影在 evaluation 上可达到 0.8848，但 API 中位延迟为 10.67 秒、估算成本约为 minimal 的 11.8 倍，而且重复样本最终切法只有 4/14 一致。这个高 F1 不足以支持将 low 设为默认。

## 实现建议

生产落地时，把当前 H1 的校验改成两级：

1. 先执行现有全文精确校验；通过则保持当前行为。
2. 失败后执行单调无损投影，使用较低建议奖励；只有一个边界都无法恢复时才回退纯 R1。

同时记录 `raw_validation_reason`、`matched_lines`、`skipped_lines`、`resyncs`、`recovered_boundaries` 和最终 `fallback`。这样可以区分“模型改了字但建议部分可用”与“完全没有可用建议”。

本轮只生成实验实现和结果，没有修改 Palmier Pro 生产代码。

---
name: voxstudio-media-workflow
description: Transcribe audio/video or generate voiceovers with the local VoxStudio app.
---

Use a dedicated interactive panel: `app_transcription` for transcription, `app_dubbing` for voiceover, and `app_session({session_id})` for results. The session library is `app_workbench({})`. UI copy is always English; transcript/script content may use any supported language.

When the user asks to transcribe a local path, call `app_transcription({path: "exact path from the prompt", start: true})` once. Absolute and `~/` paths are supported. The request itself authorizes starting transcription. Omit `language` and `speakers` for automatic detection; pass optional settings only when requested. Do not ask the user to reselect the file, confirm the language, or complete `transcription.start_form`. The tool returns a queued `job_id`; read `voxstudio.job_status({job_id})` until it returns `session_id`, then poll `media.status`. The panel also follows that job automatically. If only `transcription.create` is available, call it with the same path and omitted language. Never invent a path or claim a queued job is complete.

When the user explicitly asks to transcribe a ChatGPT media attachment, call `app_transcription({attachment: {download_url, file_id, mime_type?, file_name?}, start: true})`. Use the actual attachment object supplied by ChatGPT through `openai/fileParams`; never invent its ID, URL or a local path. Pass exactly one input, either `path` or `attachment`. Follow the returned `job_id` as above. No re-upload, file-picker navigation, language question or host form is needed. If multiple attachments exist and the prompt does not identify which one, ask only for that choice. Report a failed/expired attachment download without pretending it was transcribed.

If the user only asks to open/configure the panel, use `app_transcription({})`, or `{path, start: false}` / `{attachment, start: false}` to preselect a supplied input without starting. If no path/attachment is supplied, open the panel and let the user select media and click Start transcription. Use `media.choose_local_file` only when selection is needed. It immediately returns `job_id` with status `selecting`; poll `voxstudio.job_status` until cancellation or an `asset_id`, then poll `media.input_status` until ready. The native picker opens in VoxStudio on the Mac; do not call it repeatedly while it is open. An attachment opened through a file-viewer entrypoint uses `{name, resourceUri}` instead of fileParams; bind it with `media.bind_attachment` and keep `resourceUri` opaque. Selection/import alone never starts work. After submission, follow the returned `next_call`: if there is only a `job_id`, poll `voxstudio.job_status` with that exact ID until a `session_id` is returned; then poll `media.status` using the exact session ID and read `app_session` when completed. Keep this ID even if VoxStudio automatically changes the title. Never identify the result by filename/title, repeatedly open session lists, retry creation, or declare a queued result missing before resolving its job ID. Panel submission uses `transcription.create_from_input`. Use `transcription.start_form` only if the user specifically requests a native host form and the host advertises it. Cancel/decline never creates work. If a tool rejects an explicit input, report the concrete error; do not retry the same submission or switch to UI automation/file pickers without resolving it.

For a voiceover request that includes a script, list existing voices using `voice.list`, choose a real saved voice matching the user's preference or script language, then call `app_dubbing({text: "exact script from the prompt", voice_id: "real saved voice ID", start: true, title?, language?})` once. This submits the job and opens a panel containing the supplied script and progress. Do not open an empty `app_dubbing({})` first or separately repeat the submission through `dubbing.create`. Resolve its exact `job_id` through `voxstudio.job_status` if needed, then poll `media.status` with the returned `session_id`. Reopen the filled script and result using `app_dubbing({session_id})`; this does not generate again. A delayed/unknown response never authorizes another submission. For a client without MCP Apps, use `dubbing.create` directly with the same script and real voice ID.

If the user only asks to prepare/edit a voiceover, or still needs to choose a voice, call `app_dubbing({text, title?, voice_id?, language?, start: false})` to prefill the draft. Use `app_dubbing({})` only when no script is provided. Do not invent a reference voice or transcript. If the voice library is empty, preserve the supplied script in this filled draft and guide the user to add a reference in VoxStudio. `media.save_result` saves a completed voiceover through the system dialog.

Poll `media.status` every two seconds until completed/failed/cancelled. `media.preview` supports generated voiceover audio; `media.session_preview` provides bounded transcription audio/video. Play only on user action. A successful job submission is not a completed result. Use the independent session panel for reading/editing captions, adding translations and exporting; retain all source and language tracks.

For tools whose schema requires `request_id`, supply a fresh UUID for each intended write and preserve it on retries. Never repeat an unknown write after an App restart or after the one-hour receipt lifetime.
